# Parquet Viewer 核心设计

## 1. 产品定位

构建一个基于 Tauri 2 的跨平台只读 Parquet 查看器，支持 macOS、Windows 和 Linux。用户可拖入多个 Parquet 文件，通过多标签页查看内容，并使用可视化筛选或 SQL 查询数据。

产品重点是快速打开、稳定查看和简单查询几十 GB 的本地文件，而不是成为完整的数据开发 IDE。

## 2. 首版目标

- 拖放或文件选择器打开一个或多个 `.parquet` 文件。
- 每个文件对应独立标签页，重复打开时定位到已有标签。
- 打开几十 GB 文件时保持界面可操作，不把完整文件载入内存。
- 通过虚拟表格浏览数据，支持横向和纵向滚动。
- 提供列筛选、组合条件、排序等低门槛查询方式。
- 提供 DuckDB SQL 编辑器及智能提示。
- 查询可停止，错误可理解，内存和临时磁盘使用受控。
- 重启后恢复上次标签和 SQL 草稿，但不自动执行查询。
- 原 Parquet 文件始终只读。

## 3. 明确不做

- 编辑单元格、追加数据或写回原文件。
- 首版不做跨标签 JOIN、目录分区数据集或多个文件的合并查询。
- 不连接 S3、HTTP、数据库等远程数据源。
- 不提供图表、数据清洗、Notebook、复杂 ETL 或项目管理。
- 不追求完整数据库客户端能力。

## 4. 技术架构

### 4.1 技术选型

- 桌面框架：Tauri 2。
- 前端：TypeScript 加主流组件框架；数据表格必须使用行列虚拟化方案。
- 后端：Rust，负责会话、元数据、任务生命周期、资源限制和 IPC。
- 查询引擎：嵌入式 DuckDB，直接查询 Parquet。
- SQL 编辑器：Monaco Editor，并提供应用侧补全源。

### 4.2 模块边界

1. `FileSessionManager`
   - 维护文件路径、稳定文件 ID、标签状态、Schema、元数据和 SQL 草稿。
   - 检测文件不存在、权限变化和磁盘内容变化。

2. `MetadataService`
   - 只读取 Parquet footer、Schema、行数、Row Group、压缩方式和列统计信息。
   - 元数据读取失败不触发全文件扫描。

3. `QueryService`
   - 为当前文件创建受限 DuckDB 查询上下文。
   - 将可视化筛选编译为参数化 SQL。
   - 执行 SQL、分批返回结果、支持取消和超时提示。

4. `ResultCursor`
   - 用查询 ID 管理批次，前端按需请求下一批。
   - 限制单批行数和 IPC 消息大小；查询完成、取消或标签关闭时释放资源。

5. `SessionStore`
   - 保存已打开文件路径、标签顺序、当前标签、每个标签的 SQL 草稿和 UI 状态。
   - 不保存查询结果，不在启动时重跑查询。

6. 前端工作区
   - 管理拖放、标签、字段面板、筛选器、SQL 编辑器、结果表格和状态栏。
   - 不直接读取 Parquet，也不持有完整查询结果。

## 5. 主界面

### 5.1 空状态

- 窗口中央是明确的拖放区域：“拖入 Parquet 文件，或点击选择文件”。
- 支持一次选择或拖入多个文件。
- 显示最近打开文件，但点击后仍需校验路径与权限。

### 5.2 文件标签栏

- 每个文件一个标签，标签显示文件名，悬停展示完整路径和文件大小。
- 重复文件使用完整路径区分；同一路径不重复打开。
- 支持关闭、关闭其他、关闭右侧、重新加载、复制路径、在文件管理器中显示。
- 标签过多时横向滚动，并提供“已打开文件”下拉搜索。
- 各标签独立保存滚动位置、筛选条件、排序条件和 SQL 草稿。

### 5.3 左侧字段面板

- 显示文件大小、总行数、列数、Row Group 数和压缩方式。
- 字段列表显示字段名、逻辑类型、是否可空，并支持搜索。
- 点击字段可快速复制名称；后续版本可增加列统计详情。
- 面板可折叠，为窄屏和大量列腾出空间。

### 5.4 查询工具区

默认展示轻量工具栏：筛选、排序、SQL、刷新、停止查询和导出结果。

筛选模式使用条件胶囊：

- 操作符根据类型变化，例如文本支持 `=`、`!=`、`contains`、`starts with`、`is null`；数值和日期支持比较与区间。
- 多条件首版支持 `AND`；高级 `OR` 分组留到后续版本，避免交互复杂化。
- 排序最多允许三个字段，并明确优先级。
- 筛选和排序转换成参数化 SQL，字段名安全引用，值不拼接进 SQL。

SQL 模式在表格上方展开可调整高度的编辑器，不切换到新页面。每个文件在查询中暴露为固定虚拟表名 `data`，示例：

```sql
SELECT order_id, amount, created_at
FROM data
WHERE amount > 100
ORDER BY created_at DESC
LIMIT 1000;
```

### 5.5 结果表格

- 行和列都进行虚拟化，固定表头，首列显示结果行号。
- 支持调整列宽、自动适应、隐藏列、复制单元格/行/选区。
- `NULL`、空字符串、二进制、日期时间、嵌套值使用不同且稳定的显示规则。
- 长文本截断显示，点击后在只读详情浮层中查看完整内容。
- 默认预览最多 10,000 行，每批返回 500 行；设置中可调整预览上限。
- 不为无排序查询承诺稳定行序；界面需说明排序后结果才具备确定顺序。

### 5.6 底部状态栏

- 展示查询状态、耗时、已返回行数、是否截断、内存/临时磁盘警告。
- 查询进行中显示停止按钮。
- 错误状态提供简短原因与“查看详情/复制错误”。

## 6. SQL 智能提示

首版补全范围保持实用而有限：

- SQL 关键字：`SELECT`、`WHERE`、`GROUP BY`、`ORDER BY`、`LIMIT` 等。
- 当前文件固定表名 `data`。
- 字段名和数据类型；字段名含空格或特殊字符时自动添加双引号。
- 常用 DuckDB 标量函数、聚合函数和日期函数。
- 在 `SELECT`、`WHERE`、`ORDER BY` 等上下文中优先提示字段。
- 补全项支持模糊匹配、键盘选择和类型图标。
- 鼠标悬停显示字段类型；SQL 错误标出行列，并保留 DuckDB 原始错误详情。

首版不自研完整 SQL 语法服务器。使用 Monaco 的 completion provider，结合轻量上下文判断和 DuckDB 元数据完成提示。

## 7. 大文件策略

### 7.1 打开文件

- 打开阶段只读取 footer 和必要元数据。
- 元数据加载放在后台任务中，标签立即创建并显示加载状态。
- 不执行隐式 `COUNT(*)`；总行数优先读取 Parquet 元数据。

### 7.2 查询

- 利用 DuckDB 的列裁剪、Row Group pruning 和谓词下推。
- 前端预览查询必须带结果上限；用户导出时才允许完整结果流式输出。
- 查询结果按 RecordBatch/行批次序列化，控制单次 IPC 载荷。
- 同一标签默认只运行一个交互查询；新查询会取消该标签的旧查询。
- 不同标签允许有限并发，默认最多两个活动查询，其余排队，避免磁盘争抢。

### 7.3 资源限制

- 默认 DuckDB 内存上限取“系统可用内存的合理比例”和固定上限中的较小值，并允许用户在设置中调整。
- 允许 DuckDB 将排序和聚合的中间数据溢写到应用临时目录。
- 设置临时目录容量警戒值；不足时提前给出可操作提示。
- 标签关闭、文件重载、查询取消和应用退出都必须回收查询与临时资源。

### 7.4 分页原则

不使用对大结果反复执行高偏移量 `OFFSET` 的传统分页。交互预览采用单次查询加顺序批次游标；用户滚动时消费后续批次。这可以避免越翻页越慢和重复扫描。

## 8. 导出结果

导出不修改原文件，因此仍符合只读定位。首版支持将当前筛选或 SQL 的结果导出为 CSV；导出采用 DuckDB 流式写出，不经过前端，也不受 10,000 行预览上限约束。

- 导出前选择保存路径。
- 显示进行中状态，支持取消。
- 同名文件必须明确确认，不静默覆盖。
- SQL 有语法错误或查询被取消时不保留伪装成成功结果的目标文件。

Parquet 再导出和 JSON 导出不属于首版核心。

## 9. 会话恢复

- 正常状态下自动保存标签列表、顺序、活动标签、SQL 草稿、筛选和排序条件。
- 下次启动恢复标签，但不读取数据批次、不执行筛选或 SQL。
- 文件丢失时保留标签并展示“重新定位”与“关闭标签”。
- 文件修改时间或大小变化时提示重新加载 Schema，避免继续使用过期元数据。
- 不保存敏感查询结果或单元格内容。

## 10. 错误处理

- 非 Parquet、文件损坏或 footer 不完整：标签内显示无法打开，并提供原始错误详情。
- 文件权限不足：显示路径与权限说明，允许重新选择文件。
- 不支持的数据类型：尽量转成只读文本；无法转换时按列显示明确错误，而非让整个应用崩溃。
- 查询语法错误：编辑器定位行列，结果区保留上一次成功结果并标记其已过期。
- 内存或临时磁盘不足：中止当前查询，解释限制来源并提供设置入口。
- 文件在查询中被替换或删除：取消查询并要求重新加载。
- Rust 端错误返回稳定错误码和用户可读信息，不把 panic 暴露给前端。

## 11. 设置项

首版仅保留会影响稳定性和使用习惯的设置：

- 主题：跟随系统、浅色、深色。
- 单批返回行数：默认 500。
- 预览最大行数：默认 10,000。
- 查询内存上限。
- 临时目录与容量警戒值。
- 最多并发查询数：默认 2。
- 启动时是否恢复标签：默认开启。

## 12. MVP 优先级

### P0：必须完成

- 跨平台拖放/选择多个 Parquet 文件。
- 多标签管理与会话恢复。
- Schema 和文件元数据展示。
- 虚拟化表格、分批加载、列宽与复制。
- 类型化筛选、排序。
- DuckDB SQL 查询与字段/关键字/函数补全。
- 查询取消、内存限制、临时磁盘溢写和稳定错误提示。
- 当前查询结果导出 CSV。

### P1：稳定后补充

- 最近文件列表、标签搜索、列隐藏与布局保存。
- 更丰富的字段统计和 Row Group 信息。
- 查询历史，仅保存 SQL 文本，不保存结果。
- 更完善的嵌套类型查看器。

### 暂缓

- 多文件合并查询和跨标签 JOIN。
- 目录分区数据集。
- 远程文件与云存储。
- 图表、数据编辑、插件系统。

## 13. 验收标准

- 三个平台均可通过拖放和文件选择器打开多个文件。
- 打开几十 GB 文件时，应用内存不随文件总大小线性增长，UI 不被同步 I/O 阻塞。
- 一亿行级文件可在读取元数据后快速展示首批数据；具体耗时取决于磁盘和编码方式，测试需记录基准环境。
- 快速滚动、切换标签和重复执行查询不会造成无界内存增长。
- 关闭标签或停止查询后，相关后台任务可观察到终止并释放游标。
- SQL 补全能识别当前文件全部字段、常用关键字和函数。
- 筛选值使用参数绑定，特殊字段名得到安全引用。
- 崩溃恢复或正常重启后能恢复标签与草稿，且不会自动重跑查询。
- 导出大结果时数据不经过前端，取消后不会留下误导性的完整文件。

## 14. 测试重点

- Rust 单元测试：筛选 SQL 编译、标识符引用、会话序列化、错误映射和资源限制计算。
- 集成测试：不同编码、压缩、逻辑类型、嵌套类型、损坏 footer 和超宽 Schema 的 Parquet 文件。
- 查询测试：取消、超时、内存溢写、磁盘不足、文件查询中被替换。
- 前端测试：多标签状态隔离、恢复但不执行、虚拟滚动、过期结果标识和智能提示上下文。
- 跨平台端到端测试：拖放、文件对话框、路径字符、文件管理器定位、CSV 导出。
- 性能基准：首开时间、首批返回时间、滚动内存曲线、筛选扫描量和取消响应时间。
